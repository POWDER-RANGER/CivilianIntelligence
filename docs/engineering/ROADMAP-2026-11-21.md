# CIVINTELLIGENCE — prioritized engineering roadmap

Owner: Curtis Charles Farrar / POWDER-RANGER
Working baseline: Render `6e0a73d`, verified live 2026-11-21.
No production mutation during the initial baseline audit. Priority follows operational value and risk, not CI alert count.

## P0 — Measure and protect production

**Acceptance:** deterministic `/`, `/globe`, `/api/health`, record search, sources, auth, source provenance and WebGL validation; production datastore/provider identified; real errors classified; release health record retained.

**Current evidence:** endpoints / and /globe HTTP 200, sources and record search 200, health reports database available. Browser, OAuth, and WebGL still unverified. One prior Render `ECONNRESET`/500 requires classification.

## P1 — Public source-backed geospatial intelligence (active milestone L1)

**Acceptance:** a real external source is fetched server-side; every observation has source identity, observation time, fetch time, valid coordinates and official evidence URL; publisher and legal jurisdiction remain separate. A valid empty source is not called an outage. Invalid schema/timeout produces an explicit unavailable state; a retained last-good snapshot is never claimed current. Globe page can navigate to returned coordinates. Test invalid, empty, stale, duplicate, future-time, and concurrent requests. Required TypeScript, lint, build, CI and browser verification precede merge.

**Implementation:** official USGS significant-day feed. Node API `/api/civint/live/earthquakes` calls a bounded, rate-limited adapter with a 60s success cache, 6-hour conditional last-good fallback and typed source status. A compact, accessible /globe rail lists observations and centers the existing global viewer. It does not place a graphical earthquake marker in the separate embedded viewer.

**Remaining:** this first in-memory cache is not restart-durable; reconnect the PR #123 Python output and durable storage in L2. Local preview HTTP checks passed, but development database bootstrap reported a missing PGLite data file; browser functional validation and CI remain required. No release until those gates pass.

## P1 — Ingest-to-API durability and source registry (L2)

**Acceptance:** reconcile PR #123's `ingest/live_intelligence.py` and `earthquakes.json` schema with public API; identify storage and job runner; transactional snapshot plus timestamps persisted across Render restarts; last-good preserved on invalid feeds and outages; schema contract tests run in both runtimes; metadata/freshness displayed consistently.

**Dependency:** L1 contract accepted. Do not rewrite or reset PR #123 before comparing its remote `92535e77` and local `c3f2109` histories.

## P2 — Native production workspace (N1)

**Acceptance:** locally bundled primary UI on Windows/Linux/macOS/Android/iOS; secured native OAuth redirect/PKCE and credential storage; accessible navigation; offline saved evidence with timestamps; native transport and failure modes; representative physical-device smoke; signed builds and distribution checklist. Build and emulator green are necessary but not sufficient. Do not merge draft #121 prematurely.

## P2 — Interactive geographic layers

**Acceptance:** validated records positioned accurately, zoom/detail/filters behave in WebGL, stale and unavailable overlays are visually distinct, keyboard and screen-reader equivalents exist, no fictitious ALPR/video coverage. Provide 3D viewer integration or an explicit first-party layer rather than treating a remote camera link as a rendered marker.

## P3 — Premium UX and accessibility

**Acceptance:** typography hierarchy, WCAG 2.2 AA navigation/contrast/focus, keyboard-first interactions, large/small display and Galaxy Z Fold layouts, perceived latency and reduced-motion handling. Reconcile #96/#97 and retain unique design work.

## P3 — Sustainable release engineering

**Acceptance:** monitored p95 route and API performance, error budget, source freshness SLOs, structured safe logging, dependency update cadence, reproducible migrations, rollback procedure, canary/health gate and release notes. Never use production database migrations as a side effect of routine local build.

## Decision constraints

- No invented events or invented live-source status.
- No unauthorized production modification, no force merging, no removal of diagnostic evidence.
- No competing schedules or parallel independent release coordinators.
- Existing third-party licensing and factual source attribution are preserved.
- Owner's legitimate first-party authorship identity is respected.
